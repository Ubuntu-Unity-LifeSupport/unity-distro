## Restore procedure (R8b, L5b)

The aptly db is goleveldb: the last command's writes live in its journal
`.log` until the next open, so copying a backup over the existing directory
would mix states. Restore:
1. confirm no aptly process runs;
2. `mv` the current `db/` and `public/` aside to a dated directory (kept, not
   deleted);
3. `cp -a` the backup into the now-empty paths;
4. compare both trees, db included, with the backup's sha256 list before any
   aptly command (the first open rewrites db files);
5. read-only check: `aptly repo show unity-resolute` and the publication
   (`publish list`, which the guard blocks - listed in blocked-commands.md)
   match the backup-time state.
The restored `public/` holds plain copies instead of hardlinks into
`/srv/aptly/pool`; bytes are identical and aptly accepts existing identical
files. The R6 duration is recorded before Phase L.
